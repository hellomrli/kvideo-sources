# 维护采集源

在 [sources.json](../sources.json) 维护源主档，再运行 [check.js](../check.js) 生成订阅。需要 Node.js 20，命令在仓库根目录执行。

## 新增或调整线路

每条源记录需要以下信息：

| 字段 | 用途 |
|---|---|
| `id` | 稳定且唯一的源标识，用于报告和镜像分组 |
| `name` | 播放器显示名称 |
| `baseUrl` | 苹果 CMS V10 采集 API 地址，脚本会追加查询参数 |
| `group` | `normal` 或成人组；lite 只输出 `normal` |
| `enabled` | `false` 表示人工禁用，巡检不会请求该源 |
| `priority` | 主档记录的排序值；产物按巡检历史重新计算 |
| `origin` | 维护时记录来源，巡检产物不输出该字段 |

1. 参照主档中的完整记录添加线路，并使用新的 `id`。
2. 确认 `baseUrl` 指向采集接口。
3. 在仓库根目录运行 `node check.js`。
4. 检查报告中的列表规模、搜索结果和失败原因。

## 禁用与恢复

将主档中的 `enabled` 改为 `false`，下次巡检会记为手动禁用。恢复时将它改为 `true` 后重新巡检。自动禁用和恢复只影响生成的订阅状态，主档仍是人工维护入口。

## 用本机网络检查

以下命令使用默认关键词，并改写本地订阅、历史和报告：

```bash
node check.js
```

更换搜索词可以区分“接口失效”和“该词没有搜索结果”：

```bash
node check.js "庆余年"
```

脚本没有 `--help` 或只读巡检参数，第一个参数直接作为搜索关键词。同一天重跑时，历史中该 UTC 日期的结果会被本轮替换。

## 按失败原因排查

| 报告症状 | 检查内容 |
|---|---|
| 超时或宕机 | 本机能否访问 `baseUrl`，源是否限制地区或网络 |
| 接口返回非成功 code | API 是否仍兼容苹果 CMS，地址是否指向正确接口 |
| 库为空 | 列表响应的 `total` 是否为有效正数 |
| 搜索无结果 | 关键词是否存在，以及 `ac=detail&wd=` 是否可用 |
| 保留观察 | 近期仍有成功记录，查看[订阅规则](inspection.md) |

自动任务会在修改 `sources.json` 时、每日定时或手动触发时运行，并提交五份产物。只修改产物不会成为长期源配置。
