# 巡检与订阅规则

巡检中的“当日成功”、订阅中的“启用”和镜像判断表示不同状态。理解这些区别，才能正确解释播放器中保留的线路。

## 两步检查

首先请求 `?ac=list`，检查 HTTP 响应、JSON、可选的成功 code 和正数 `total`。随后请求 `?ac=detail&wd=`，要求搜索结果列表非空。默认关键词为“斗罗大陆”。

每个请求的超时是 12 秒，并发数是 12。列表请求遇到网络异常最多尝试两次；搜索检查只执行一次。通过这两步并不等于验证了搜索结果中的每个播放地址。

## 历史、观察和优先级

历史按 API 地址匹配，每个 UTC 日期只保留一次结果，最多保留 30 条每日记录。成功率的分母是该源实际出现的历史次数，未检测日期不补成失败或成功。

线路在以下任一条件下保持启用：当日成功；或最近 7 条历史中至少成功一次，且连续失败少于 3 天。人工禁用优先于这些规则。

当日成功的源按成功率分为优先级 `1`、`5`、`10`；失败源为 `100 + 连续失败次数`；人工禁用为 `999`。所以 clean 和 lite 中可以出现当天失败但仍保留观察的源，它们的优先级会降低。

## 候选镜像

只有当日通过、且 `total > 1000` 的源才参与镜像分组。`total` 相同的线路被视为候选镜像，组内按优先级和 ID 保留首选线路，其余地址写入 `mirrorUrls`。

库存数相同是启发式判断，不能证明两个站点拥有同一后端。报告会列出完整分组，便于人工复核或切换备用地址。

## 报告与网络位置

报告时间显示为北京时间，历史日期使用 UTC。定时任务从 GitHub Actions 所在网络检测，家庭宽带或 NAS 的可用性可能不同。本地运行可提供自己的网络视角。
